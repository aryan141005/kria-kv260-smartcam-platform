# Vitis Platform and Hardware Acceleration

## 1. Overview

AMD Vitis is used in the SmartCam development workflow to configure the software platform and support hardware acceleration on the Kria KV260.

It uses the hardware handoff exported from Vivado to create a platform that can be used for application and acceleration development.

## 2. Platform Creation

The Vitis workflow begins with the XSA generated by Vivado.

The major steps include:

1. Import the exported XSA hardware handoff.
2. Create a Vitis platform project.
3. Configure the processing system and platform settings.
4. Generate the platform outputs.
5. Prepare the platform for hardware acceleration development.

## 3. DPU Hardware Acceleration

The SmartCam reference workflow includes a Deep Learning Processing Unit (DPU) acceleration component.

The DPU is designed to accelerate supported deep-learning workloads using programmable logic.

The acceleration workflow involves integrating the DPU kernel with the target hardware platform.

## 4. Acceleration Build Outputs

The reference workflow includes the following hardware-related artifacts:

| Artifact | Purpose |
|---|---|
| `dpu.xo` | Compiled Vitis kernel object |
| `system.bit` | FPGA programmable-logic bitstream |
| `dpu.xclbin` | Compiled acceleration binary |
| `bit.bin` | FPGA configuration binary used by the overlay |
| `shell.json` | Metadata associated with the acceleration overlay |

These artifacts support the hardware acceleration and deployment workflow.

## 5. Hardware Acceleration Workflow

The high-level process is:

1. Import the Vivado-generated hardware platform.
2. Configure the Vitis platform.
3. Integrate the required DPU acceleration component.
4. Compile the acceleration kernel.
5. Generate the required hardware and acceleration outputs.
6. Prepare the overlay artifacts for integration with the embedded Linux environment.

## 6. Integration with Embedded Linux

The generated hardware and acceleration artifacts are intended to be integrated with the PetaLinux environment.

The programmable logic can be configured using the generated bitstream, while the acceleration binary and associated metadata support the runtime acceleration workflow.
